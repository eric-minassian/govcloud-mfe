# 0005 — Shared singletons and one query cache

**Status:** accepted

## Context

Federated modules are built separately but run on one page. Libraries that keep module-level
state break in subtle ways if two copies load: hooks fail, contexts don't match and caches
split. These include React, the router, TanStack Query and our own SDK contexts.

## Decision

- Share `react`, `react-dom`, `react-router`, `@tanstack/react-query`,
  `@govcloud-mfe/platform-sdk` and `@govcloud-mfe/ui` as **singletons**. The `shared` map is
  generated by `@govcloud-mfe/mf-config` from the installed versions, so every app declares
  it the same way.
- One version of each dependency for the whole repo, using the **pnpm catalog**.
- `requiredVersion` is the major version (the minor version for `0.x`). A remote built against
  a newer minor still runs on the shell's copy, and a major mismatch is reported at runtime.
- The **shell owns the single `QueryClient`.** Remotes never render their own
  `QueryClientProvider`; their standalone dev harness does. Platform data (`currentUser`,
  `modules`, `featureFlags`, `preferences`) is defined once as `queryOptions` in the SDK, so
  every module hits the same cache entry. Module-owned keys are namespaced with
  `moduleQueryKey('<module>', ...)`.

## Consequences

- Cross-module coordination happens through the cache with no event bus. Saving preferences in
  Settings re-themes the shell immediately.
- Upgrading React, the router or TanStack Query to a new major version is a coordinated,
  platform-wide change: the shell first, then each remote rebuilds.
- Query-key discipline is a convention. A lint rule or SDK-provided `useModuleQuery` wrapper
  could enforce it later.
